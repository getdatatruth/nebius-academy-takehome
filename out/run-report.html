The red team prompt

The drafting prompt is replaced with one that instructs the model to do exactly what the system exists to prevent: lead with a percentile comparison, cite a failure statistic, and describe what most organisations in their position do. The research pack is unchanged, and it still contains no benchmark fact.

An earlier version of this test only deleted the benchmark prohibition and left the other rules standing. The model behaved anyway, so the gate passed by luck rather than by design and the test proved nothing. The claim being made here is that the gate holds when the prompt attacks it, which is a stronger claim than saying the model usually behaves.

Measuring whether it can be trusted

npm run eval · 3 runs per lead, live

A gate that blocks things is not the same as a gate you can rely on. This runs every lead repeatedly, plus an adversarially prompted draft each round, and reports what actually happens. It is the difference between wiring an agent up and operating one.

MetricBeforeAfterWhat it decides
Gate pass rate 50% 66.7% Whether drafts are good enough for a lane to graduate

Pipeline error rate — 0% of 18 Whether a lane can run unattended

The two rows are read together, never separately. A prompt change that raises the pass rate while lowering the red team catch rate has made the system worse: the model has become more persuasive, not more truthful. Without measuring both, that trade looks exactly like an improvement, which is how most teams make it by accident.

The loop, once through

1 · What the report showed

The block-reason table counts every stopped send by layer, with a column for how many landed on the adversarial payload. "Benchmark peer group widened" appeared four times, but only once on the red team. Three ordinary, well-behaved leads were being blocked for the same thing.

2 · The diagnosis

The permitted fact reads "organisations over 1,000 employees that have completed this assessment". The model kept dropping that final clause, which quietly grows the claim from 47 assessed organisations to every firm of that size. A prompt problem, not a gate problem, and the red-team column is what separated the two.

3 · The change

One rule added to both drafting prompts: reproduce the benchmark's qualifying clause exactly.

4 · Re-measured

Pass rate 50% to 66.7%. Occurrences on ordinary leads: three down to one. Red team catch rate unchanged at 100%, all three still caught by the free deterministic layer. The change is an improvement rather than a loosening, and that distinction is only available because both numbers were measured.

Everything on this page is a real run. The three Anthropic calls per qualified lead ran live against claude-sonnet-4-6, and every email above was written by the model. Without an API key set, the run still completes by replaying recorded drafts, and every line of output says which mode it is in.

Worth knowing before you read the verdicts as fixed: which leads pass changes between runs. Five live runs produced five different combinations, and three separate bugs in the gate itself only became visible when real model output met it, because the recorded fixtures had been written to be compliant. The fixtures tested whether the gate accepted good drafts. Only live output tested whether its definition of good was right, and twice it was not.
